Autonomy is a spectrum you configure, not a switch you flip

Agentic systems carry a fundamentally different risk profile from static models, because they write as well as read. The architecture question is not "can it act" but "what may it do unattended."

Enterprise AI Architect · Director, AI & Data Management Point of view

The requirement this answers

“Architect agentic AI solutions with appropriate guardrails and human oversight”

Define, per workflow, what the agent does unattended, what needs approval, and what is never automated.

The three-tier boundary

For every agentic workflow I write down three lists. Unattended: retries, schema re-inference, enrichment, classification proposals. Requires approval: any logic change, any policy change, anything that alters a published number. Never automated: deletion, policy override, access grants, anything irreversible without a recovery path.

This is boring, and it is the entire difference between an agent programme that survives its first incident and one that does not.

Earn autonomy, don't assume it

Every agent starts in propose-only mode. It moves to bounded auto-apply only after a clean proposal record over a meaningful sample — not after a good demo. Confidence thresholds are risk-tiered: the bar for merging two customer records in a marketing database is not the bar for merging them in a regulated safety database.

Logging, oversight and audit capability go in before agents touch real systems, not after the first finding.

Where agents genuinely earn their keep

Multi-step transactional work that needs tool-calling and write access. Autonomous incident response — detect, correlate across lineage, hypothesise, validate in a sandbox, present for approval. Legacy logic archaeology, parsing old ETL metadata to recover business rules nobody documented. These are high-leverage because the human bottleneck was never the typing.

How I apply it

  • Write the autonomy boundary per pipeline before the agent is built
  • Run propose-only first; graduate on evidence, with a documented threshold
  • Give every agent an audit trail a compliance officer can read
  • Keep humans on the loop for policy and edge cases, off the loop for routine work

What good looks like

  • You can produce the autonomy matrix for any agent in production
  • Steward queues shrink over time because the system learns
  • Incidents produce retrievable context, not just resolved tickets
  • Nobody is surprised by what an agent did
