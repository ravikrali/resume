The semantic layer is the layer everyone skips and everyone needs

Natural-language querying over raw physical tables produces fluent nonsense. The fix is unglamorous: one governed definition of each entity and metric, plus a graph for the relationships.

Enterprise AI Architect · Enterprise Data Architect Point of view

The requirement this answers

“Design RAG, knowledge graph and semantic search architectures”

Retrieval quality is a data modelling problem wearing an AI costume.

Why vector search alone falls short

Embedding similarity finds passages that read like the question. It does not know that a study has sites, that sites have investigators, that investigators have prior enrolment performance, and that the question "which sites should we consider" requires traversing all three.

Multi-hop questions need structure. That is what a knowledge graph provides, and it is why the strongest enterprise implementations are hybrid: graph for relationships, vector for language, both governed.

What I built at Parexel

A knowledge LLM pipeline joining structured clinical metadata to unstructured protocol documents through a RAG architecture — so operational teams could ask questions in natural language and get governed, auditable answers about a global study portfolio. Intelligent search, protocol summarisation, site and investigator insight. Analyst research time fell by roughly 60%.

The part that made it work was not the retrieval strategy. It was that clinical metadata had already been mastered and the semantic relationships were explicit.

Design rules I hold to

Agents query the semantic layer, never the physical schema. Extraction, classification and embedding are governed pipeline stages that inherit lineage and policy like any table. Retrieval accuracy is measured with an eval harness, per use case, and tracked over time — because retrieval silently degrades as the corpus grows.

How I apply it

  • Model entities and relationships first; choose the retrieval strategy second
  • Hybrid retrieval — graph traversal plus permission-aware vector search
  • Treat the vector index as a governed data asset with an owner
  • Build the eval harness in the first sprint, not after the complaints

What good looks like

  • The same metric definition serves the dashboard and the agent
  • Retrieval precision is a tracked number with a trend line
  • Answers cite their source documents and a user can open them
  • Access control holds when the same question is asked by two different people
